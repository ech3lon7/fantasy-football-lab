## Gameday Plus redesign, Phase 9 (five added features) November 10 2026

- Added, each as tested read-only domain code in `src/domain/view/` before any screen. **Start or sit odds** (`odds.ts`, shown in versus): the chance one player outscores the other from each player's EPPG and spread, treated as independent and normal (an Abramowitz and Stegun normal CDF, exact at the centre), worded "close to a coin flip", "a modest edge" or "a clear edge" and labelled an estimate from past variability, not a prediction; no figure when an EPPG or spread is missing or there is no variability. **League power ranges** (`power.ts`, under the League grade grid): each team's current-week starting lineup total with a combined spread (floor, expected, ceiling), ranked, plus the owner's chance of outscoring each other team by the same method. **Add and drop pairs** (`add-drop.ts`, on Roster): for each of the 25 best available players the drop that helps most under the existing rules (droppable players only, a legal roster afterwards, ties by the lower surplus index then the player id), with lineup gain ± spread, "Starts at X" or "Depth only", a switch for depth-only rows, and "Try in a simulation", which appends a cut and an add as two undoable moves to the active hypothetical roster; pairs whose best drop costs lineup points are not listed, and a test shows the simulator accepts a pair's moves and changes ownership both ways. **Since last import** (`since-import.ts`, on This week): when an import replaces a dataset the app first stores a small per-player summary of the old one (names, active labels, Expected PPG) and the next screen lists labels gained and lost and the largest Expected PPG movers; the section is hidden when there is no previous import or nothing changed, a missing EPPG is never treated as zero, and new players are not compared. **Counter-offer builder** (`counter.ts`, a fourth Trade room tab): from the Manual analyzer's offer it tries every one-swap and one-add alternative, keeps those that still help the owner's lineup, shows both lineups' change with the owner's spread, puts counters that help both teams first, and offers "Use this" (loads it into the analyzer) and "Log as counteroffer" (adds a pending journal offer noted as a counter-offer).
- Owner decision made and flagged: the previous-import summary is kept on the device only, in a separate account-scoped record, and is never uploaded or synced (the synced state is size-limited, as the gem tracking journal already is). `docs/architecture.md` and the app's sidebar text now say the app keeps one current snapshot plus a small summary of the previous import, not the workbook. The summary is written on every import, whichever interface is selected.
- `npm run check` passed with 62 test files and 644 tests; the production build passed; the browser suite passed 169 tests with 1 skipped (private workbook). New browser workflows cover versus odds (or the plain note when a spread is missing), the power table, the add and drop section and its switch, the since-last-import digest from a stored summary and its absence without one, the Counter-offers tab and "Use this", and dark mode. Excel parity checks were not run because no valuation or trade-value code changed; the new code only reads existing results.
- Not done in Phase 9: the synthetic browser league is too small for a real add and drop pair or a guaranteed counter-offer, so "Try in a simulation", "Use this" and journal logging are covered by domain tests and the empty-state browser paths, not by a full browser run of each; counter-offer search runs on the main thread when the button is pressed (about a second for a five-player offer) and has no cancel; the digest cannot compare grades, owners or injuries (the brief marks those as later). Nothing committed.

## Gameday Plus redesign, Phase 6 part 2 (single search method and chain presets) November 10 2026

- Added `src/domain/search-limits.ts`, the single search method. Four shared limits (minimum final gain 2.0 EPPG, maximum temporary loss 0, maximum recipient value loss 20%, index window) default to the former Balanced values with the **index window Off**, as the owner decided, so existing automatic searches keep their meaning and no window is silently switched on. Only edited limits are stored (`searchLimits`); an "edited" marker shows on the section header (also when folded) and on each changed slider. Applying the limits to a chain query makes price tests warnings, so none hides a result; applying them to a Find trades query maps Off to automatic index matching and a number to the strict range. Widening starts from the user's own values in two further steps and names every limit that moved and by how much (an Off window never gains a window). Chain results are ordered: every price test passed, then price warnings, then widened results, without dropping any. A saved search or preset carrying a strictness level migrates by dropping that level and keeping everything else. The limits are not stored inside presets.
- Chain presets are now ten: "Surface-stat opportunities" is renamed "Surface-stat trading" (id unchanged, earlier saved label text maps to the new name), and "Fix my weakest position" and "Buy low, then flip" are added. The first adds a +2 step upgrade goal at the team's lowest-graded starting position and a two-step drop limit at the other positions; the second requires a BUY LOW arrival in trade one and a SELL HIGH departure in trade two, enforced per leg. Preset-added goals and labels are removed when another preset is chosen while goals set by the user stay. `applyChainPresetKeepingLimits` guarantees a preset never changes the shared limits.
- In the Trade room, Find trades and the Chain planner now show one shared, foldable Search limits section; inside the current tools the strictness setting, the strict-index checkbox, the chain mode, gain, loss, recipient and broadening fields and the price-test choice are replaced by a note pointing to it. This applies only in the preview, through a context; without it every current control behaves exactly as before.
