**Goal:**
- **What it's for:** MPPG is a number for **this week only**, the here and now. The owner uses it to pick starters. EPPG remains the forward-looking season number and keeps its role in valuation and trades.

MPPG adds half of the gap between the owner's Expected PPG and ESPN's season projection, so the model's view of the player carries into the week.

## 0. Ground rules

- **Separate number.** MPPG is new. These stay exactly as they are, and Excel parity must not change:
  - Expected PPG, Value PPG, VORP and the surplus index;
  - grades, the lineup used for trade evaluation, and every trade verdict.
- **Imported week only.** MPPG exists only for the week whose ESPN weekly projections were imported. There is no MPPG for future weeks, and none is estimated.
- **Where each number leads:**
  - MPPG leads wherever the question is "who do I start this week": This week, Roster, start-or-sit odds, Weekly streamers, the "this week" view of add and drop pairs, and the player card header.
  - EPPG leads wherever the question is value over the season: Trade room, League grades, Scouting default sort, surplus and VORP.
- **Null is never zero.** A player with no MPPG shows the reason and is excluded from the weekly lineup; he is never counted as 0 points.
- All calculation in `src/domain`; UI components do not repeat the formula; synthetic fixtures only.

## 1. The formula (`src/domain/mppg.ts`)

For player *p* in the imported week:

1. **Availability.**
   - If *p*'s team has no game that week (`ModelSchedule.HasGame` 0 or bye), return `{ value: null, reason: "Bye week" }`.
   - If `InjuryStatus` is OUT, INJURY_RESERVE/IR or SUSPENSION, return `{ value: null, reason: "Out" }`.
2. **ESPN weekly.**
   - If `Current_Week_Projection` (`p.weekly`) is missing or unusable, return `{ value: null, reason: "No ESPN weekly projection" }`.
   - **Do not fall back to EPPG.** EPPG is still shown beside it.
3. **Model edge.**
   - edge = `MPPG_EDGE_WEIGHT` × (EPPG − `ESPN_Projected_PPG`), with `MPPG_EDGE_WEIGHT = 0.5` as a named constant.
   - If EPPG or ESPN season PPG is null, the edge is null. MPPG is then ESPN weekly alone, with source `"espn-only"` and the reason shown.
4. **MPPG** = max(0, ESPN weekly + edge).
5. **Spread:** the player's existing blended spread, the next-refresh spread already used for floor and ceiling.
   - Floor = max(0, MPPG − spread).
   - Ceiling = MPPG + spread.
6. **Return** `{ value, spread, floor, ceiling, espnWeek, edge, eppg, espnSeason, source: "blend" | "espn-only", reason, importedAt }`, so the UI can show how it was built: "ESPN week 11.4 − ½ × 0.3 (EPPG 8.7 vs ESPN season 9.0)".
7. **Freshness.** `importedAt` is the timestamp of the import that supplied `Current_Week_Projection`. Show "as of import …" wherever MPPG leads. ESPN revises weekly projections during the week, and MPPG is only as fresh as the last import.

Questionable or doubtful players keep their value, plus a status tag; ESPN's weekly figure carries that information.

- [ ] **1.1 Tests:**

  - EPPG 2 above ESPN season adds +1;

  - a large negative edge floors at 0;
  - bye → null with "Bye week", and never 0;

## 2. Weekly lineup (`src/domain/lineups.ts`)

- [ ] **2.1** `weeklyLineup(m, team)`:
  - Use the **existing** slot rules, ranking by MPPG. Players with null MPPG are not eligible.
  - Return the slots, the total MPPG of the starters, and the total spread (root-sum-square, the same method as lineup gain).
  - Also return the season lineup's MPPG total, for "+1.9 over your season lineup".
- [ ] **2.2 Suggested swaps: compare starter sets, not slots.**
  - Find the players who start in the weekly lineup but not the season lineup ("in"), and those who start in the season lineup but not the weekly one ("out").
  - Pair the best "in" with the worst "out", and so on. Two receivers changing places between WR1 and WR2 is **not** a swap.
  - Each pair is "Start X over Y", with the MPPG difference and the chance X outscores Y. The chance is Φ(difference ÷ √(spread_X² + spread_Y²)), the same method as start-or-sit odds.
  - The reason line gives ESPN's two weekly projections, plus the matchup chip text as context.
  - If Y has no MPPG, show Y's reason ("on bye", "Out") instead of numbers.
- [ ] **2.3** Trade evaluation keeps the season lineup; `weeklyLineup` is never called from trade code (static test).
- [ ] **2.4 Tests:**
  - identical rosters give identical lineups;
  - a bench player with a higher ESPN weekly projection moves into FLEX;
  - two starters changing slots produce no swap;
  - a bye starter is replaced and the reason is "on bye";
  - totals and spreads match hand calculations.
