# Manager expectations and Trade journal

- In Trade analyzer or Find matching trades, enable **Match manager expectations** when you want the new assessment. It starts off; your existing calculations and filters remain independent.
- Choose the manager's saved preset or override it for that search. **Trade journal → Manager profiles** stores the five-level negotiating stance, explicit cornerstones and attributed observations. Unknown managers use League baseline.
- Your before/after EPPG stays private model scoring. Their surface lineup uses best legal season-average scoring. Elite-return safeguards check the main return and distinct starter compensation. A negative overall surface gain alone does not automatically fail a trade.
- An estimated acceptance range is provisional, not demonstrated predictive accuracy. Expand **Why this estimate?** for required versus actual numbers, outgoing losses, named replacements and score contributions. Legacy surface-gain and other active filters still apply when separately enabled.
- Each chain stage has its own enablement/override and uses that stage's roster. The app does not multiply its two estimated ranges into a chain probability.
- Results group by opponent and primary target. Expand alternatives to inspect every exact offer, and **Show more** to load later pages. Existing Save trade and Load trade actions remain available.
- **Log offer + original forecast** explicitly saves a pending offer and its original source/settings/evidence. Searching alone does not log offers or real responses. Record the actual outcome in Trade journal; counters are linked offer versions.
- Import documented records through **Import documented trades** using the journal supplement workbook or exported journal JSON. Review the preview. Historical evidence is separate from prospective forecasts; identical imports do not overwrite newer outcomes.
- Journal records save locally and sync privately with the existing signed-in Fantasy account. **Sync journal now** and the main **Sync now** use record revisions. Resolve genuine conflicts per record; failed sync never disables ordinary trade saving/loading. Export the journal for an additional private copy.
- Updating player data never replaces the sole original forecast. Prospective tracking includes only forecasts recorded before real opposing responses, with complete displayed estimates. Practice, user responses and retrospective replay do not become opponent-validation successes.

The journal uses migration `002_negotiations.sql`, isolated from other applications' tables. Real workbooks, journal exports and source snapshots must remain outside public repository assets. App release numbering and publication remain explicit user actions.
